# PIX Football - Architecture Contract

Unity 6000.6.6f1, HDRP 17.6, C#, Input System. Windows standalone (D3D12) target, Xbox controller first. There is no Steamworks integration (no SDK, app id or depot config in the project); distribution is a zipped Windows build attached to a GitHub release (`Docs/RELEASING.md`).
Default editor path used by the scripts: `C:\Program Files\Unity\Hub\Editor\6000.6.6f1\Editor\Unity.exe` (override with the `UNITY_PATH` environment variable, see `Tools/unity.ps1`).

## Golden rules
1. **No placeholder art.** Visuals come from the user's Draft Fever assets (imported under
   `Assets/_Licensed/`), Blender-generated meshes, Tripo or PixelLab. Never ship capsules/greybox.
2. `Assets/_Licensed/` and `_AssetSource/` are **git-ignored** (licensed art stays local; repo is public).
   Code must never hard-reference `_Licensed` GUIDs from committed assets in a way that breaks
   compilation when the folder is missing - load through `ArtLibrary` (a registry ScriptableObject in `PixFootball.Art`).
   In the editor `ArtLibrary.Load()` reads the full library at `Assets/_Licensed/ArtLibrary.asset`; in a player it falls back to
   `Resources.Load("ArtLibrary")`. `ArtLibraryBuilder` therefore also copies the library to `Assets/_Licensed/Resources/ArtLibrary.asset`,
   and `BuildScript` swaps that copy for a slim whitelisted one while building (restored afterwards, see `Docs/RELEASING.md`).
   The committed scenes (`MainMenu`, `Stadium_Pro`, `Match_Pro`) are generated by `PIX Football > Scenes > Build All` and DO reference the
   stadium prefab from `Assets/_Licensed/DraftFever/Prefabs`: a fresh clone without the licensed folder opens them with a missing prefab until
   the licensed art is restored and the scenes are rebuilt. `Assets/_Project/Animations`, `Art` and `Prefabs` are intentionally empty
   placeholders (generated output lives under `_Licensed`).
3. Football logic is **pure C#** (no UnityEngine types except `Mathf`-free math in `PixFootball.Core`),
   deterministic with a seeded `Rng`. Unity-side code only adapts it.
4. Everything data-driven: ScriptableObjects wrap Core data for authoring; JSON for saves.
5. Every system gets EditMode tests in `Assets/_Project/Tests/EditMode`.
6. Only original names/branding in generated content.

## Units & coordinates
- Field: X = sideline-to-sideline (width 53.33 yd), Z = goal-line axis. 1 Unity unit = 1 meter;
  `Yards.ToMeters = 0.9144`. Core works in **yards**; Gameplay converts.
- Core field position: `BallSpot` 0..100 yards from offense's own goal line.

## Key Core types (contract - keep these names)
- `Rng` (xorshift128+, seedable, `NextFloat()`, `Range(int,int)`, `Gaussian()`).
- `Position` enum: QB,RB,FB,WR,TE,LT,LG,C,RG,RT,LE,DT,RE,LOLB,MLB,ROLB,CB,FS,SS,K,P.
- `Ratings` struct: Speed, Acceleration, Agility, Strength, Awareness, Catching, Carrying,
  ThrowPower, ThrowAccuracy, Tackling, BlockShedding, RunBlocking, PassBlocking, ManCoverage,
  ZoneCoverage, Jumping, Stamina, Injury, KickPower, KickAccuracy, BreakTackle, Elusiveness (0-99) + `Overall(Position)`.
- `RuleSet` (data): `Pro` and `College` presets - feet in bounds, overtime format, clock-stops-on-first-down,
  hash width, PAT distance, two-point, quarter length, timeouts, challenges.
- `GameState`: quarter, clock seconds, down, distance, ball spot, possession, score, timeouts;
  `Apply(PlayResult)` advances it deterministically (first downs, TDs, safeties, turnovers, change of possession, end of quarter/half/OT).
- `Penalty` catalog + enforcement.
- `Playbook` -> `Formation` -> `PlaySet` -> `Play` (offense: per-slot `Assignment` = Route/Block/Run path; defense: Coverage/Rush/Zone).

## Time steps and build settings (decisions as of v0.6, recorded not changed)
- **Three clocks.** The simulation steps at a fixed 60 Hz (`PlaySimulation.Dt = 1/60`), fed the frame time by `MatchDirector` and advanced in fixed steps through an accumulator (`PlaySimulation.Tick`); the replay recorder samples at 30 Hz (`LateUpdate`); Unity physics runs at its project default of 50 Hz (`ProjectSettings/TimeManager.asset`, Fixed Timestep 0.02). They are deliberately decoupled: the sim never uses `FixedUpdate` or `Time.fixedDeltaTime`, and the only code on the physics step is the ragdoll (`RagdollRig.FixedUpdate`, bodies on a layer that collides with an invisible ground plane). Ragdoll bodies are blended with the sim-driven view in `LateUpdate`; their rigidbodies have `interpolation = None`, so at frame rates that are not a multiple of 50 Hz the ragdoll steps can show as judder (the audited QA-984 symptom). Remedies if it shows in play: turn rigidbody interpolation on in `RagdollRig`, or set Fixed Timestep to 1/60. If a future pass needs lock-step physics, set Fixed Timestep to 1/60 in `TimeManager.asset` (nothing else reads the value).
- **Scripting backend.** `ProjectSettings.asset` leaves `scriptingBackend`, `managedStrippingLevel` and `il2cppCodeGeneration` empty for every platform, so the Windows standalone player is built with the Unity default (Mono, default managed stripping). IL2CPP has not been evaluated or measured; the 60 Hz sim for 22 agents currently meets the frame-rate numbers in `CHANGELOG.md` on Mono. Changing the backend (or testing a stripping level, which can remove reflection-used types) is a separate, measured decision; if it is made it must be recorded here and in `Docs/RELEASING.md`.
- **Contact clip roles (A / B).** Two different conventions exist and must not be mixed up. (1) The *paired* keys (`contact_tackle`, `contact_sack`, `contact_bighit`, `contact_collision`, `catch_contested`, handoffs, blocks): `ArtLibraryBuilder` registers the `_A` clip of the pair under `<key>` and the `_B` clip under `<key>_b`; actor A is the offense (carrier / quarterback / receiver) and actor B the defender, as `ContactTable` and `ContactSession` assume (and as `BuildScript`'s whitelist comment says). (2) The older *single-actor* keys (`tackle_wrap`, `tackle_dive`, `tackle_arm`, `be_trucked` from `*Dmo_A` takes; `be_tackled`, `truck` from `*Omo_A` takes) are chosen by the `Dmo` (defender motion) / `Omo` (offense motion) part of the clip name, not by the `_A` / `_B` suffix. There is no per-clip role table beyond the pair order in `PixContact.asset`.

## Gameplay feel targets (ESPN NFL 2K5)
- Locomotion is momentum based: velocity integrates toward desired velocity with accel from ratings,
  turn rate falls with speed and mass. No instant direction change.
- Root-motion mocap from Draft Fever (BoNES/Motus retargets) layered over physics-driven capsule.
- Outcomes come from simulated positions + ratings, not dice.

## v0.2 match architecture
```
MainMenu --Play Now--> TeamSelectPanel (UI) --GameSession.StartMatch(MatchConfig)--> Match_Pro scene
Match_Pro:  MatchDirector (Gameplay) --- IMatchPresentation ---> MatchHud (UI)
            |-- MatchFlow (engine-free: GameState + PhysicalGameSim coordinator + PlaySimulation per snap)
            |-- PlayStage  (22 SimAgentViews pooled by body size + BallFollower; PlayFrame mapping)
            |-- MatchCameraRig (Cinemachine: broadcast / behind / first person / debug close-up)
            |-- FieldMarkers (blue LOS, yellow first-down strip, ring under the user's player)
            `-- MatchAudio
```
- **MatchFlow** (`Gameplay/Match/MatchFlow.cs`) has no Unity types: `PrepareSnap` (burn the runoff, report period changes), `CpuCalls` / `DefenseAnswer`, `OffenseOptions` / `DefenseOptions` (the 4-6 plays on A/B/X/Y/LB/RB), `CreateSim`, `Finish` (apply to `GameState`, classify the outcome for banners / stats). The accelerated clock is `MatchConfig.RunoffScale` (1.0 = rule-book runoff, about 60-70 snaps for 5-minute quarters).
- **Coordinates** (`PlayFrame`): the simulation always has the offense driving toward +Y. `PlayFrame.For(possession, quarter)` rotates the frame 180 degrees about the vertical axis when the offense attacks the -Z end zone (X and Z both mirrored, so handedness is kept). Home attacks +Z in odd quarters, -Z in even ones; the broadcast camera moves to the side that makes the offense drive left to right.
- **Animation**: `SimAgentView.ApplyMatch` feeds locomotion (velocity / facing) to the controller inside a `PlayableGraph` (`ActionAnimator`: layer mixer, controller at the bottom, one clip on top with manual time, fade in / out, loop / hold). `AnimKit` maps each `AgentAction` to ArtLibrary clip keys; `ClipTimingTable` (built by `ClipTimingBuilder`) gives the throw-release and catch moments so the clip is trimmed to line up with the ball. Paired takes (`<key>` for the first actor, `<key>_b` for the second) are used for engaged blocks, handoffs, tackles and sacks, aligned by variant name. Carrier moves (juke, spin, stiff-arm, truck, hurdle, dive) reuse the v0.1 action layer.
  **v0.8 animation pass**: every ArtLibrary clip is a cleaned `Animations/Clean/*.anim` (muscle-space cleanup, +Z facing baked in, grounded feet; originals untouched, see `Docs/AssetInventory.md` section 14). `ActionAnimator` has two clip slots (the newest clip always sits on the upper mixer input, so a replacing clip is a real cross-fade with smoothstep weights), a loop `Phase`, and an upper-body `AvatarMask` for throws / catches / hand-offs made on the move. The controller has two data-driven locomotion trees (players / ball carriers via the `Protect` bool, `AnimHints.Carrying`) whose clips are placed by their MEASURED stride speed and travel direction; every player has his own `CycleOffset`. `AnimKit` adds kicks (`Kick`, foot contact from `ClipTimingTable`), `GetOff` at the snap, `Block` = pass-pro footwork, exact-twin pairing (`TryPair` / `TwinOf`) and logs a missing key once; `StanceRules.ClipKeys(kind, role)` picks one of 16 per-position stance keys. Cross-fades are never shorter than `ActionAnimator.MinFade` (0.22 s). The cleaned clips have no foot IK goal curves: clip playables must always run with Foot IK off (`SetApplyFootIK(false)`; offline tools use `AnimPlay.PlayClip`), otherwise the legs fold. Tools: `AnimAudit`, `LegCheck`, `StickSheet` (writes to `D:/PIXFootball/Renders/animation`), `ClipCleaner` / `CleanBatch` / `DerivedClips`, `AnimRebuild`, `AnimSequenceCheck`, `BatchWatchdog` (hard time limit for batch runs).
- **Kicks / punts**: there is no kicking mocap in the source set. `SimAgentView.LateUpdate` drives the right hip and knee procedurally (back-swing, contact at 0.12 s, follow-through) over the running animation when the simulation reports `AgentAction.Kick`.
- **User control**: `MatchInput` polls the pad / keyboard directly (no input-action asset). The director picks the controlled agent (QB pre-snap; ball carrier; intended receiver while a pass is in the air; the defender nearest the ball) and only hands him to the simulation when the user is actually steering, so the AI keeps playing the rest of the time.
- **Autotest**: `MatchDirector.ForceAutopilot` / `Autopilot` makes the director play the user's side; `AutoTest` listens to `PlayStarted`, `PlayFinished`, `SimEvent` and `Milestone`, and `MatchCameraRig.CloseUp` takes close shots of tackles, catches, throws and kicks.

## v0.3 play calling, pre-snap and penalties
```
Core:      Playbook (Formation Family/SetName) - PlayEditing (clone, mirror, hot route, slide) - PlayDiagram (route/block/zone geometry)
           PlayCaller (CPU + Ask Coach) - AudibleBook / DefenseAdjust - PlayCallModel (pure navigation view-model) - PenaltyEnforcer.Describe
Sim:       PlaySimulation.PreSnap (ChangeOffensePlay, FlipOffense, SetHotRoute, SetSlideProtection, SetMotion, SetDefenseAdjust, CallDelayOfGame)
Gameplay:  MatchFlow(.PlayCall) builds the PlayCallModel, penalty choices and referee text; MatchDirector(.PreSnap) polls input and drives everything
           MatchOfficials (7-man crew + coaches) - FieldMarkers.SetHashMarks (college ticks)
UI:        PlayCallScreen + PlayDiagramGraphic, PreSnapPanel, PenaltyPanel, UiPrompts - all rendered from models the director hands over
```
- **Play-call screen**: `PlayCallModel` (Core, engine-free) holds tabs, stage (Formation -> Set -> Play), filters, paging (3 cards), flip, timeout request and expiry; `MatchDirector.DriveCallScreen` maps pad input onto it and `PlayCallScreen` renders it. Sets are the formation variants of a family (offense) or coverage groups (defense).
- **Pre-snap changes work on clones**: `PlayEditing` never mutates the playbook; `PlaySimulation.PreSnap` swaps `OffPlay` / `DefPlay`, rewrites every agent's `Assign`, re-lays out alignments (flip, shifts, press) and re-prepares the AI. Motion is a pre-snap walk (`PreSnapWant`).
- **Penalties**: `PenaltyEnforcer.Describe` clones the state to compute both options; `MatchFlow.Finish(sim, decision)` applies the choice; `MatchDirector.PenaltyFlow` shows the panel (user) or the CPU's expected-points choice.
- **College rules**: `PlayFrame.For(GameState)` keeps both overtime possessions at one end zone; hash X comes from `FieldGeometry.HashX(hash, rules)` in the sim; `FieldMarkers.SetHashMarks` paints the 40-foot hashes.
- **Playbook review**: `PIX Football > Tools > Render Playbook Atlas` (or `PlayCardPainter` in a console harness) renders every play to `Docs/Playbook/*.png`.
- **Autotest**: `MatchInput.ScriptMode` + `Enqueue` feed scripted frames through the real input path (`AutoTest.V3.cs`).

## v0.4 contact, ragdoll and performance
```
Art:       ContactTable (PixContact.asset)      measured root / hips / heading paths of every authored two-actor take + contact moment, approach geometry, get-up timing
           MoveTakeTable (PixMoveTakes.asset)   usable windows inside the long BoNES takes (the spin)
           PlayerMeshLodTable (PixMeshLods.asset) simplified torso / legs / arms / hands / shoes / head meshes
Editor:    ContactClipBuilder (Build Contact Table / Build Move Takes / contact sheets), PlayerMeshLodBuilder, HdrpTuning, PerfDiagnostics
Gameplay/Contact:
           ContactMath      Rigid2 alignment, bearing, warp / authority weights, array sampling (pure, tested)
           TackleVariants   TackleType + contact angle + speed -> best authored pair (pure, tested)
           ContactSession   one pair played against the simulation: align at contact, warp in, follow the animation root motion, hand back to the sim (pure)
           ContactDirector  sim events -> sessions, gang tacklers / drags (hold), contested catches, stiff-arm IK, truck / pancake knock-backs, get-up takes
           RagdollStateMachine (pure) + RagdollRig (bodies, joints, ground plane, blend)
Gameplay/Player:
           BodyMotion       spine lean / pitch, stance-foot lock, stiff-arm and protect-ball arm IK (LimbIK = analytic two-bone solver, pure)
           PlayerLod        distance LOD of helmet / mask / body meshes
Gameplay:  CollisionFeel (camera trauma shake + Xbox rumble), QualityTiers (Low / Medium / High / Ultra + render scale)
```
- **Authored pairs.** Every Draft Fever tackle / sack / big-hit / contested-catch take is two clips (`_A` = the offense: ball carrier, quarterback, receiver; `_B` = the defender). The default import re-bases each clip to its own start, which throws the authored layout away, so `ContactClipBuilder` imports the pair clips once with "Root Transform Position (XZ) Based Upon: Original", records where each actor starts in the shared mocap scene, reverts to Center of Mass (the clips still play in place at the view origin) and stores `root(t)` and `hips(t)` of both actors in that shared frame. v0.2 / v0.3 played the A clip on the tackler and the B clip on the carrier; v0.4 has the roles right.
- **Alignment.** At a tackle event `ContactDirector` picks the pair with `TackleVariants.Choose` (kind from the sim's `TackleType`, bearing of the tackler in the carrier's frame, carrier speed, closing speed), builds a `ContactSession` that puts the authored carrier hips on the simulated carrier (position exact, heading blended with the contact axis) and plays both clips from 0.18 s before the authored contact. The views warp from the simulation onto the animation root path over that lead-in (`ContactMath.WarpIn`), follow it exactly for 0.3 s after the hit and then blend back to the simulation (`ContactMath.Authority`) so the carrier ends where the sim says he is.
- **Gang tackles and drags.** A `Drag` event plays the pair up to 0.5 s after contact and freezes it (`ActionAnimator.SetFrozen`) while the sim carrier churns on; the next tackle event for that carrier releases it. Extra defenders play the B clip of another pair aligned to the carrier's pose.
- **Ragdoll.** `RagdollRig` builds Humanoid-bone rigid bodies, capsule / box colliders and character joints lazily from the avatar's bind pose; bodies sit on a layer that only collides with an invisible ground plane. Animation to ragdoll is a 0.12 s pose blend (the animated pose pulls the bodies), 0.4 to 1.2 s of simulation with capped velocities, then the settled pose is blended into a get-up take cut from the lying-and-rising part of the authored tackle takes, chosen by the face up / down test.
- **Performance.** The 80,000-vertex match player was the cost: the 26,000-vertex helmet and the 11,000 vertices of hands and shoes drew into every shadow cascade 22 times. `PlayerLod` swaps the gear to its authored LOD01 / LOD02 and the body to clustered meshes by distance; coaches and officials are not posed off screen and the coaches cast no shadows.
- **Autotest.** `-pixAutotestContactOnly [-pixAutotestContactCases wrap,bighit,...]` scripts one play per case with the `PlaySimOptions.ForceTackle` / `ForceTackleAfter` test hooks, `MatchDirector.ForcedCall` / `AutoMove` and takes a close-up screenshot sequence of each contact into `Logs/autotest`.
- **Sim changes** are engine-free and deterministic: the quarterback reads a hot-routed receiver from the snap and favours him (`OffenseAI.HotReadEdge` / `HotReadBonus`); the two test hooks default to off.

## v0.5 broadcast layer
```
Gameplay:      IBroadcast (BroadcastHooks.cs) - the only thing MatchDirector knows about the broadcast layer
               MatchCameraRig.SetOverride (Cinemachine brain off, live cameras keep tracking) + SetLookAssist / head bob (first person)
               PlayStage.WalkTo / PlayReaction (celebration choreography), MatchOfficials.CoachTransform / SetCrewVisible, UpscalerControl
Presentation:  BroadcastDirector (partial: core, Shots, Shows, Debug)  implements IBroadcast, added to the match scene (also by a sceneLoaded bootstrap)
               Replay/    ReplayData (QuatPack, ReplayClip, ReplayLibrary), ReplayRecorder, ReplayPlayer (actors), ReplayView (angles + free camera), ReplayController (auto / manual / reel), ReplayHud
               Director/  ShotRules (pure), ShotLibrary (camera moves), BroadcastCamera (override camera + HDRP depth of field), HighlightScorer (pure)
               Stats/     GameTracker (live box score, drives), OverlayText, Commentary (ICommentaryHook + CommentaryBus)
               Overlays/  TvOverlays (cards in four slots), TvUi (procedural parallelogram sprites)
               World/     CrowdReaction, FirstPersonFx
               BroadcastAutoTest (registered in AutoTest.ExtraParts)
UI:            MatchHud (pause: Instant Replay + Cinematics, SetReplayMode, SetHudMinimal), SettingsPanel (4 pages)
```
- **Wiring.** `MatchDirector.Start` finds the `IBroadcast` component (`Match` object) and calls `Attach`; every hook is a null-checked call, so the game plays exactly like v0.4 without it. The broadcast layer never owns game state: it reads the finished `PlayOutcome`, the simulation (`PlaySimulation.Log`, agents), the stage views and the game state.
- **Instant replay: record, not re-simulate.** The simulation is deterministic per play, but what the viewer sees is not a function of it: the contact director warps players onto authored tackle takes, the ragdoll is physics, clip variants and the carry arm depend on view state and input timing. `ReplayRecorder` therefore stores what was shown. Every 1/30 s (in `LateUpdate`, after animation, IK and the ball) it writes the root pose of the 22 views, the local rotation of every animated bone (smallest-three packing, 4 bytes; `BoneSet` = skinned bones plus their ancestors, same order for every body of a size), the hip / root-bone positions and the ball. About 6-10 KB per sample, 2-3 MB for a play, 0.2 ms per sample. Pre-snap samples older than 1.1 s are dropped at the snap. `ReplayLibrary` keeps the newest 8 plays plus the 12 most exciting (`HighlightScorer`) inside a 90 MB budget. Playback (`ReplayPlayer`) poses 22 plain avatars (no animation graph) from the interpolated samples: pure function of (clip, time), so scrubbing, slow motion and rewind are exact.
- **Camera hand-over.** `BroadcastCamera.Begin` turns the Cinemachine brain off and drives the main camera directly (position, rotation, field of view). Depth of field uses the HDRP physical camera: the camera becomes a 36 x 24 mm sensor with the focal length from the shot's field of view, `Camera.aperture` and `Camera.focusDistance` set the blur and a global volume with a `DepthOfField` override (physical camera mode) fades in. `End` is an instant cut back to the live cameras, which kept tracking underneath. TAA is swapped for FXAA for three frames after a cut.
- **Director rules** (`ShotRules`, tested): nothing with Cinematics Off; a pre-snap shot only when the play clock leaves at least 0.6 s of live view after it (max 2.6 s) and ends the instant the snap happens (`OnPreSnapFrame(snapping)`); establishing shots on the first play of the game (sky swoop), of a drive (sky / sideline QB / end zone, rotating) and, in Minimal, the second half; post-play: tight carrier shot, touchdown celebration plus crowd or coach, turnover coach reaction, an occasional crowd shot, always inside the 5.2 s budget. The automatic replay runs after the wind-down for plays scoring above the threshold (45 Full, 60 Minimal) and is skippable with A.
- **Stats.** `GameTracker` builds a real box score for the live game (player lines, team box scores, drives with plays / yards / time of possession / result, scoring events) from `PlayOutcome` + the players on the field; the lower-thirds, drive summaries, team comparison, halftime and postgame shows read from it (`OverlayText`).
- **Overlays** live in four screen slots (lower left, right side, lower right, centre) so they never overlap each other; the scorebug / banner / hint bar of the HUD sit outside those slots. Cards are procedural (parallelogram sprites drawn into textures), UI-kit colours, Saira Condensed / Barlow, crests from the kit.
- **Crowd.** The fan billboards have two poses in the atlas (seated, arms up) one atlas row apart; a reaction scrolls each chunk's atlas window by one row in a wave around the bowl (`CrowdReaction`), with additive camera-flash sprites at seat positions. The crowd meshes are built in 18 m chunks for this.
- **Autotest.** `-pixAutotest` runs the broadcast segment after the v0.4 segments (`AutoTest.ExtraParts`); `-pixAutotestBroadcastOnly` runs only it. It writes `bc_*.png` to the output directory and logs FPS for live play and for replays / cinematics. `-pixUpscaler 0|1|2` overrides the upscaler.

```
Shaders (Assets/_Project/Shaders):
   PixLit/   PIX/Lit = a copy of HDRP/Lit (PixLit.shader, PixLitProperties.hlsl, PixLitData.hlsl) with ONE hook (PixLitHooks.hlsl: PixSurfaceHook) called after GetSurfaceData.
             _PixMode 0 stadium surfaces (wet / puddles / ripples / snow), 1 turf, 2 uniform, 3 helmet shell, 4 field markings.

```
- **Surface gradient.** HDRP Lit shades with surface-gradient normal mapping, so the `normalTS` inside the hook is a surface gradient (zero = flat, never normalise it). Bumps are added (`normalTS += PixGradFromTex(...)`), flattening scales it down. Treating it as a unit normal produced NaNs (whole frame black through bloom) before this was understood.
- **Per player uniform.** One `PIX_Uniform_V6` material instance per pooled avatar (the v0.5 path already did this). Number, number colours, dirt vectors are plain material properties set when a view is dressed for a play (`LookDirector.Dress`) or soiled by an event. The shader draws the digits from the atlas on four placements (back, front, two sleeve caps; `PixLookAssets.number*`), so there are no render textures and no decals per player.
- **Dirt.** `DirtModel` is pure: events add to four body regions with a saturating curve scaled by wetness and surface; the shader maps the regions texture (baked in Blender from the mesh, `Tools/Blender/bake_player_regions.py`) through a threshold on a noise texture so dirt grows from spots into patches.
- **Field.** One wear texture for the whole pitch instead of pooled decal projectors: tackles stamp soil / mud, running leaves worn lines, snow games leave dark footprints; snow refills them (`WeatherClimate.Snow`).
- **Weather is data.** `WeatherPresets.Get(kind, time)` -> `WeatherPreset` (sun, sky, fog, floodlights, wetness, snow, grade, ball slickness). `WeatherSystem.Apply` is the only place that turns it into Unity objects. `MatchDirector.SetupLook` resolves the team-select choice with the game seed.
- **Look gallery / before-after.** `-pixAutotestLookOnly` pauses a real game at a pre-snap and at the first tackle and photographs 6 framings under 7 presets; `PixLook.Legacy` swaps every avatar back to the v0.5 shader graphs and turns the weather volume off so the v0.5 look can be shot at the very same moment (`look_*_v05.png`).
- **Edit-mode look dev.** `PixFootball.EditorTools.V6Shots.Dev` renders posed players and weather in the stadium scene in batch mode in about a minute (args `-v6weather -v6time -v6set ...`).

## v0.6 stances, facing and the user camera
```
Art:      ClipFacingTable (Resources/PixClipFacing.asset, git-ignored)  heading of every mocap clip on a match avatar + hand / foot handedness + mirror-image twin clip
Gameplay/Player:  StanceRules   pure: StanceKind per position / alignment / formation, pre-snap facing, yaw maths           (EditMode tested)
                  StanceClips   StanceSpec -> looping clip window (preferred takes, mirror twin by side of the ball, audited middle of the take)
                  BodyHeading   hips / shoulders heading, feet, hands, head height of a posed Humanoid
                  SimAgentView  clip facing offset (table, feed forward) + closed-loop hips heading correction (feedback) + 3-point setback
Gameplay/Cameras: UserCameraMath  pure: Classic / Madden / Wide presets, pull-back at the snap, carrier follow, defense framing  (EditMode tested)
                  UserCameraView  sim -> camera input (shared by the director and the gallery);  MatchCameraRig drives the "Behind" Cinemachine camera from it
Editor:   ClipFacingAudit (PIX Football/Assets/Build Clip Facing)   StanceGallery (-executeMethod PixFootball.EditorTools.StanceGallery.Run)
```
- **Root cause of "OL / DL / CBs face backwards".** The match avatar carries one fixed yaw (`PlayerAvatar.ModelYaw`, -90) that is right for the Motus locomotion cycles only. Every other pack is authored facing another way on that rig: the Motus line stance +133 deg, the linebacker idles -153..-170, the BoNES studio and quarterback takes -90, the Motus block takes 180, the quarterback shuffles used for back-pedal / strafe -63 / -131 / -135. Nothing corrected it, so only 5 % of the players faced the right way in the gallery.
- **Fix (two layers).** `ClipFacingTable.Offset(clip)` (measured offline by `ClipFacingAudit`) turns the body while the clip's weight is up; `SimAgentView.UpdateFacingLoop` then measures the hips heading every frame in LateUpdate and turns the body onto the simulation heading for plain locomotion / stance / block actions (throws, spins, tackles and falls really turn the hips and are left alone). A stale or missing table therefore degrades gracefully: the loop converges anyway, and a clip whose length changed since the audit is ignored with a warning. Rebuild the table after every `Build ArtLibrary` / clip re-import.
- **Stances** come from `StanceRules` (position + alignment + formation, never the clip pool): C snap stance, OL / DL / TE on the line 3-point (goal-line interior 4-point), QB under center / shotgun, WR split vs slot, LB two-point, CB press (within 3.2 yd) vs off, safeties deep, gunners, returners, kickers. `StanceClips` picks the take, preferring the real stance takes by name, and the mirror-image twin (Humanoid mirror setting, built by the audit) when the side of the ball wants the other hand down / the other foot back. Lines pull back 0.36 m from their simulated centre while in their stance so the helmets meet across the ball.
- **Formation Gallery** (`Docs/QA/stance_gallery/`, `Docs/QA/stance_camera.md`): plays the real `PlayStage` for 28 scenarios (every offensive and defensive formation, kickoff, onside, punt, field goal, PAT, two-point, kneel, spike) in both attack directions and checks facing (simulation and body), stance clip, stance height, foot side, T-pose and live consistency numerically, then renders top-down / behind-QB / sideline / line close-up pictures with arrows (green = simulation facing, cyan / red = body). `-pixGalleryMode camera` renders the user-camera sequences to `Docs/QA/camera/`. `-pixNoClipFacing` measures the "before" state.
- **User camera.** `CameraMode.Behind` is the user-play camera: `Classic` (All-Pro 2K8: ~9 m up, 17 m behind the line, ~26 deg down, 46 deg lens), `Madden` (lower and closer) and `Wide`. Offense: behind the offense looking downfield; defense: behind the defense looking at the offense; kicks: behind the kicker / returner. At the snap it pulls back and up (zoom-out setting) and follows the ball carrier from behind with a lead. The TV broadcast camera is used for CPU-vs-CPU games and as an option (Settings > Camera, View button cycles Classic / Madden / Wide / first person / broadcast). With a human playing, the broadcast director cuts nothing before the snap and keeps post-whistle cuts under 3 s.

## v0.7.0 animation feel (Track A): weight, the real quarterback, commit windows, ball sync
```
Gameplay/Player:  SimAgentView.Flow    commit windows (Priority / CommitFilter / NoteCommit), GamePace pacing of non-event clips, the quarterback flow (QbFlow: stance -> distance-matched drop -> pocket -> pump -> scramble -> throw)
                  SimAgentView.Ground  FitGround: stationary clips (stance / idle / pass-pro) lowered / raised so the lowest sole point rests on the turf (bind-pose ankle / toe heights)
                  AnimKit.V7           QbPocket / QbDrop / QbThrow / QbPump plans from the derived pixqb_* clips (+ Lead(): event-timed catch and hand-off)
                  BodyMotion           + ClampToes (toe-out clamp), Carriage (QB chest / ear, press-corner hands up) over LimbIK, LocoTrim (experimental stride loop, off)
                  ActionAnimator       + Scrub / SetScrub (clip time set by the caller), SetSpeed, RemainingSeconds
                  LocomotionAnimator   + StrideTrim table, faster slow-down follow, Trim hook
Gameplay/Match:  PlayStage.Flow       FlowAction (receiver reaches before the ball arrives, QB + back start the hand-off take before they meet, kick clip eta), AddFlowHints, celebration hand
                  BallFollower         release / attach offset blending (no pop at the release or the catch), Hand mode (the ball stays in one hand through a touchdown celebration), QB carriage poses
Sim (read-only hooks, additive): PlaySimulation.QbDropPoint / QbDropSteps / QbRolling / QbHandoffTargetId / QbPlanIsHandoff, PlaySimOptions.QbWindupSeconds (0 = calibrated default; the match sets 0.42)
Editor/Tools:    AnimQbBuilder  derived clips + timing + keys (additive)     AnimSplayFix  foot-twist data fix of the locomotion cycles     AnimLocoRebuild  controller only
                  AnimQbShots    real-PlayStage film strips, treadmill / stance / kick / catch numbers (D:/PIXFootball/anim_qb)     AnimFeel  foot splay, key dump, clip profile
```
- **Commit windows.** Each simulated action has a priority (`SimAgentView.Priority`: tackle / fall 9, celebration 8, kick 7, throw / catch / hand-off 6, jump and carrier moves 5, engaged / shed 3, block 2, locomotion 1). A plan that starts for a committable action (throw, catch, hand-off, jump, kick, celebration, the explosion out of a stance) is not replaced by a lower-priority action until about 85 percent of it has played; the simulation's own commit windows (`GamePace`) and these compose (the sim holds the state, the view holds the clip).
- **Event-timed clips.** The view reads ahead where a clip has to land on a simulated event: the intended receiver's catch starts `eta` before the ball arrives (hands together on the catch frame), the quarterback and the back start the hand-off take about to meet (`ClipTimingTable` exchange moment), the kick clip is slowed or started part-way so its contact is `PlaySimulation.KickContactTime`, the throw take is stretched to the simulated wind-up (`PlaySimOptions.QbWindupSeconds`) so the release frame is the ball launch.
- **Derived clips.** `AnimQbBuilder` finds the release of every BoNES throw take (peak forward hand speed while the hand is cocked above the chest), cuts `pixqb_throw_set / _run / _away`, writes the release into `PixClipTiming` (`t` = release, `t2` = wind-up start, `d` = metres of travel for drop-backs) and builds held stances (`pixstance_wr / qb_under / cb_off / cb_press / rb`). `ClipTimingBuilder` clears the table: run `AnimQbBuilder.BuildAll` after it, then `ClipFacingAudit`.
- **Foot data fix.** `AnimSplayFix` measures the toe-out of each foot at ground contact on the photoreal body for every locomotion cycle and adds a constant offset to the three twist muscles of that leg (originals in `Animations/Clean/_backup_splay`). Re-run it after `CleanBatch`.

## v0.10.0 choreography

v0.10.0 choreography: `Sim/Choreo/Choreographer` (engine-free, deterministic, no RNG) sits next to `PlaySimulation`. Each tick, after the AI and before the bodies step, it forecasts tackles and catches 0.5 to 1.2 s ahead and bends the paths with a bounded velocity change (`Steer`); at the contact it books a take (pair by bearing, speed, height, side) and from then on the sim body's position and facing follow the take's root path (`Follow`), warped in and handed back at the take's exit moment. The Unity layer (`ContactDirector.Choreo`, `SimAgentView.Choreo`) only starts the clip at the booking's clip time and releases it when the sim does; it hands the legs to MOTION's locomotion with `LocoRelease` / `LocoTakeBack`. The library of takes is `GameChoreoLibrary` (from `ContactTable` and `ChoreoTable`); tests use a synthetic library. Defensive backs' hip flips are planned in `Choreographer.Turn`.
